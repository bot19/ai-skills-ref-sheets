01

Template to running

Rebuild step 1

In Rider: New Solution → ASP.NET Core Web API, net10.0, C#. Or the CLI, which also makes the .gitignore to add before your first commit:

dotnet new sln -n Hello           # Hello.slnx: workspace root (.slnx is new in .NET 10)
dotnet new webapi -n Hello.Api     # the only project that runs
dotnet sln add Hello.Api
dotnet new gitignore               # ignores bin/ and obj/, the build output
dotnet run --project Hello.Api     # then GET http://localhost:<port>/weatherforecast

Program.cs is the whole app, and it has two halves. Everything before Build() registers what exists. Everything after it sets up what happens to each request.

The template, trimmed

var builder = WebApplication.CreateBuilder(args);
// 1 · REGISTER: what exists (the container)
builder.Services.AddOpenApi();

var app = builder.Build();

// 2 · PIPELINE: what each request passes through
if (app.Environment.IsDevelopment())
    app.MapOpenApi();
app.UseHttpsRedirection();
app.MapGet("/weatherforecast", () => { ... });
app.Run();

record WeatherForecast(DateOnly Date,
    int TemperatureC, string? Summary);

What each part is

Add…()

Puts a service in the container. Order mostly doesn't matter. ≈ wrapping your app in providers.

Use…()

Adds middleware: a step every request passes through, in the order written. ≈ Express app.use().

MapGet()

A minimal API endpoint: a route plus a lambda, defined in Program.cs. ≈ Express app.get('/x', fn).

MapOpenApi()

Serves a generated JSON description of every endpoint at /openapi/v1.json, in Development only. The template has no Swagger UI page.

/ returns 404 because only /weatherforecast is mapped. The weather is random, made up on every call. The record at the bottom is explained in §03.

02

Switching to FastEndpoints

Rebuild step 2

Minimal APIs pile every route into Program.cs. FastEndpoints, a NuGet package, gives each endpoint its own class instead: request type, handler and response type together. user.service uses MVC controllers, which group many endpoints into one class.

Install (v8.3) and register · both lines needed

dotnet add Hello.Api package FastEndpoints

// Program.cs, register half
builder.Services.AddFastEndpoints();

// Program.cs, pipeline half
app.UseFastEndpoints();
// ↑ finds every endpoint class in the
//   project, once, at startup

Or Rider's NuGet window. Packages must support your target framework, so upgrading .NET means upgrading them too.

Endpoints/HelloEndpoint.cs

public class HelloRequest
{
    public string Name { get; set; } = "";
}

public class HelloEndpoint
    : Endpoint<HelloRequest, string>
{
    public override void Configure()
    {
        Get("/hello");
        AllowAnonymous();
    }

    public override async Task HandleAsync(
        HelloRequest req, CancellationToken ct)
    {
        await Send.OkAsync($"Hello, {req.Name}", ct);
    }
}
PieceWhat it doesFront-end equivalent
Endpoint<TReq, TRes>The base class. The two type arguments (generics) fix what comes in and what goes out, and the compiler holds the handler to both.Handler<Req, Res> in TS
Configure()Runs once at startup: HTTP verb, route, auth rules.the route definition
HandleAsync()Runs on every request, with the request already bound from query, route and body.the handler function
Send.OkAsync(x, ct)Writes status 200 and x as JSON.res.json(x)
CancellationTokenFires if the client disconnects. Pass it to anything slow.AbortSignal
AllowAnonymous()FastEndpoints endpoints require auth by default. Leave this out with no auth set up and every call returns 500.[AllowAnonymous] on a controller
02

Pick the base class by its shape

Four variants
Base classRequestResponseUsed in Hello for
Endpoint<TReq, TRes>typedtypedGET /hello, POST /people
EndpointWithoutRequest<TRes>nonetypedGET /people, a plain "give me the list"
Endpoint<TReq>typeduntypednot used; for endpoints that return no body
EndpointWithoutRequestnoneuntypednot used; a ping or health check

The request has to be a class. The binder fills properties by name (?name=Elly goes into Name), and a string has no properties to fill. Mark's first attempt hit this; it's the third error below.

C# words met in passing

With the TypeScript you already know

Who can see it

publicAnyone, in any project. The class's public contract.
internalOnly code in the same project. The default for a class with no modifier.
protectedThe class and its subclasses.
privateOnly the class itself: its internals.

Easy to miss with four projects. Write class Person without public and it is internal to Domain. Api then fails to build with CS0122: 'Person' is inaccessible due to its protection level. Rider's templates add public; hand-typed classes don't.

Inheriting from a base class

abstractCan't be created with new; only subclassed. Endpoint<,> is abstract.
virtualA base method that subclasses may replace. Configure and HandleAsync are virtual.
overrideReplaces the base version completely.
base.X()Calls the base version from inside your override. ≈ super.x()

Asked in the session: after an override, does the base Configure() still run? No. It runs only if you call base.Configure() yourself, and FastEndpoints doesn't need you to. static means something belongs to the type, not an instance. Endpoints aren't static, so the framework creates instances of them.

04

Splitting into four projects

Rebuild steps 3–4 · recap: Week 1 "The four projects"

One project works, but anything can then use anything. Splitting it gives each layer its own compiled project, and the references between them become the rules. Week 1 covers why; this is how.

Create and reference

dotnet new classlib -n Hello.Application
dotnet new classlib -n Hello.Domain
dotnet new classlib -n Hello.Infrastructure
dotnet sln add Hello.Application Hello.Domain \
               Hello.Infrastructure

# "X reference Y" = X is allowed to use Y
dotnet add Hello.Api reference Hello.Application \
               Hello.Domain Hello.Infrastructure
dotnet add Hello.Application reference Hello.Domain
dotnet add Hello.Infrastructure reference Hello.Domain

Delete each Class1.cs. In Rider: Add → New Project → Class Library, then Add → Reference on the project.

The trap Mark hit: three web projects. Made from the wrong template, Application, Domain and Infrastructure each got their own Program.cs, appsettings.json and launchSettings.json. Only Api runs, so only Api should have them. Check the first line of each .csproj: Sdk="Microsoft.NET.Sdk.Web" for Api, plain Microsoft.NET.Sdk for the rest.

Hello.Domain · the nouns

namespace Hello.Domain.Entities;  // project + folder

public class Person
{
    public string Name { get; set; } = "";
    public int Age { get; set; }
}

Hello.Domain · the contracts

namespace Hello.Domain.Interfaces;

public interface IPeopleRepository
{
    Task<IEnumerable<Person>> GetPeople();
    Task AddPerson(Person person);
}
// IPeopleService: the same two methods

A namespace follows the folder path, and using Hello.Domain.Entities; is the import. Interfaces: Hello puts both in Domain. Many codebases keep a service interface like IPeopleService in Application, since only Api calls it. IPeopleRepository must be in Domain: Infrastructure implements it, and here Infrastructure can't see Application.

05

Wiring it together

Rebuild steps 5–6 · recap: Week 1 "Who builds these objects?"

Each class lists what it needs in its constructor, and the container supplies it. Two ways to write that, which compile to almost the same thing:

Classic · a backing field

public class PeopleService : IPeopleService
{
    private readonly IPeopleRepository _repo;

    public PeopleService(IPeopleRepository repo)
    {
        _repo = repo;
    }

    public Task<IEnumerable<Person>> GetPeople()
        => _repo.GetPeople();
}

Primary constructor · C# 12+, what Rider suggests

public class PeopleService(IPeopleRepository repo)
    : IPeopleService
{
    public Task<IEnumerable<Person>> GetPeople()
        => repo.GetPeople();

    public Task AddPerson(Person person)
        => repo.AddPerson(person);
}
05

readonly, and what it doesn't stop

Wiring, continued
_repo = other;Outside the constructor: compile error CS0191: A readonly field cannot be assigned to. The reference is fixed.
_repo.AddPerson(p);Allowed. readonly fixes which object you point at, not what's inside it. ≈ a TS const holding an array: no reassigning, but push still works.
repo = other;On a primary-constructor parameter: compiles. Easy to miss: these parameters aren't readonly, so the shorthand drops the guard. Nobody reassigns injected services in practice, so both styles are fine.

Hello.Infrastructure · the list

public class InMemoryPeopleRepository
    : IPeopleRepository
{
    private readonly List<Person> _people =
    [
        new() { Name = "John", Age = 20 },
        new() { Name = "Jane", Age = 21 },
    ];

    public Task<IEnumerable<Person>> GetPeople() =>
        Task.FromResult<IEnumerable<Person>>(_people);

    public Task AddPerson(Person person)
    {
        _people.Add(person);
        return Task.CompletedTask;
    }
}

Hello.Api · Program.cs, register half

builder.Services.AddFastEndpoints();

// "when someone asks for the interface,
//  give them this class"
builder.Services.AddSingleton<
    IPeopleRepository, InMemoryPeopleRepository>();
builder.Services.AddSingleton<
    IPeopleService, PeopleService>();

Api is the only project that references all the others, so it's the only place that can name both the interface and the class. This is the single line you'd change to swap in a database.

The repository isn't really async. It returns Task anyway, so a database version can drop in without changing any caller.

Lifetimes

Why the repository has to be a Singleton

Objects = lists
Singleton + Singleton 
AddSingleton<IPeopleRepository, …>
AddSingleton<IPeopleService, …>

One repository for the life of the process. POST Mary, then GET:

John · Jane · Mary

Restart the app and Mary is gone. The list was never saved anywhere.

Scoped + Scoped 
AddScoped<IPeopleRepository, …>
AddScoped<IPeopleService, …>

A new repository, and so a new list, for every request. The POST adds Mary to a list that's thrown away when its response goes out:

"Person added" · then John · Jane
Scoped repo + Singleton service 
AddScoped<IPeopleRepository, …>
AddSingleton<IPeopleService, …>

In Development the app refuses to start:

Cannot consume scoped service 'IPeopleRepository' from singleton 'IPeopleService'

This is the captive dependency from Week 1.

LifetimeThe container…Fits
Singletonbuilds one, the first time it's needed, and hands it to everyone until restartHello's in-memory list · caches · API clients
Scopedbuilds one per HTTP request, shared by everything in that requesta real database repository: the data lives in the database, not in the object
Transientbuilds a new one every time anything asks, even twice in one requestan open question from the session; see §09

Syntax shortcuts

// collection expression (C# 12) ≈ [ ... ]
List<Person> people = [ a, b ];
// target-typed new: type taken from the left
Person p = new() { Name = "Mary" };
// object initialiser: no () needed
new Person { Name = "Mary", Age = 30 };
// interpolation ≈ `Hello, ${name}`
$"Hello, {req.Name}"
// expression body ≈ arrow function
public Task X() => repo.X();

Return IEnumerable<T> (≈ Iterable<T>), not List<T>, so the repository can change its storage without changing callers.

Adding a feature: POST /people

Rebuild step 7 · five places, top-down

Once the layers are wired, every feature is the same walk. Mark wrote each call before the method existed, then used ⌥↩ (Alt+Enter on Windows) to create it in the interface and implement it in the class, one layer down at a time.

1Api

AddPersonRequest + AddPersonEndpoint

2Domain

IPeopleService.AddPerson

3App

PeopleService.AddPerson → repo

4Domain

IPeopleRepository.AddPerson

5Infra

_people.Add(person)

↻restart

New endpoint, so restart, or you get a 405.

public class AddPersonEndpoint(IPeopleService service)
    : Endpoint<AddPersonRequest, string>
{
    public override void Configure()
    {
        Post("/people");
        AllowAnonymous();
    }

    public override async Task HandleAsync(
        AddPersonRequest req, CancellationToken ct)
    {
        await service.AddPerson(new Person
            { Name = req.Name, Age = req.Age });
        await Send.OkAsync("Person added", ct);
    }
}

The refactor at the end: AddPerson(string name, int age) became AddPerson(Person person). Rule of thumb: at about four parameters, pass one object instead, as you would in JS.

ShapeLives inIsWhy it's separate
PersonDomainthe entity: the thing as the system stores itgrows Id, CreatedAt… that clients must never set
AddPersonRequestApithe request DTO (data transfer object: properties, no behaviour): exactly what the client may sendit's the public contract; changing it can break callers
response modelApiwhat goes back: maybe the person plus a message or error codesHello returns a bare string for now

Homework and what's next

  • Rebuild Hello solo from the order on page 1, then add an endpoint of your own. A real data source (the Supabase ESL dictionary came up) is a new repository in Infrastructure behind a Domain interface; endpoint and service shouldn't change.
  • Mark's question: for a stateless helper (say, one that returns "Hello " + name), which performs better, Transient or Singleton? Hint: count the objects the container builds over 1,000 requests. And still open: when would you actually want Transient?
